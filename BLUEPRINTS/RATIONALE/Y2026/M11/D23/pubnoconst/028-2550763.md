## Problem

1. **Tweets cut off at the bottom.** Collage cards capped `.tweet-embed-container` at `max-height: 22rem` with `overflow: hidden`, and `revealTweetFluidly` clamped its target height to that cap as well.
2. **Two-phase pop-in.** `waitForStableHeight` force-revealed after a fixed 950 ms, settling after only 140 ms of quiet. Slow tweets were revealed at a partial height and then snapped to full when the inline height was cleared.

## What Twitter actually does

This was measured in Chrome by listening to the `twttr.embed` postMessage protocol from the widget iframes:

```
~1.0s initialized -> ~1.4s results -> ~2.9s resize(h) + rendered   (createTweet() resolves here)
                                     ~4.0s resize(h')              (photo tweets only, after media loads)
```

The iframe height is already exact when `createTweet()` resolves. There is nothing to "settle", so any fixed wait is pure latency. The only genuine second phase is the extra `resize` from media tweets.

## Decisions

- **No timers.** As soon as the iframe has a real height, the slot animates from the ripple spacer to that height (the card body is pushed), and the tweet eases in 140 ms behind the push. An intermediate attempt with a 600 ms quiet window plus an 8 s cap was rejected in UI review: it waited too long and hid the ripple.
- **Measure the iframe, never the stage.** Once in flow, the stage is a flex item that stretches to the container, so measuring it fed the container's height back into itself and collapsed the slot to about 118 px. `frame.offsetHeight` (plus the stage's padding) is also immune to the stage's scale-in transform. The stage is `flex: none; align-self: flex-start`.
- **Follow, don't snapshot.** A `ResizeObserver` on the iframe keeps the slot's explicit height in sync for the lifetime of the card. Twitter's second phase and viewport-width changes retarget the same CSS height transition, so they become a smooth push instead of a jump or a clip.
- **Overlap Twitter with Turso.** On the async catalog shell, `widgets.js` is requested at page load, in parallel with the `/journals/content` fetch, rather than after the cards arrive. Measured time to first reveal went from about 2.3–2.9 s to about 1.1 s.
- Removed the collage `max-height: 22rem` clip. Tall tweets make tall cards, which is the intended trade-off.
- Asset cache keys bumped: `journal-media.js?v=11` (catalog, entry, and editor), `site.css?v=13`, `journals.css?v=6`.
