## 1. Tweet ripple trapped in the tweet slot

**Symptom:** while a tweet loaded, the ripple appeared only around the tweet's media space, not across the entry card.

**Cause:** `createMedia()` calls `renderTweet(container)` before its caller appends `container` to the card. `showRippleLoader` resolved `container.closest(".journal-card")` at that moment, got `null`, and fell back to the container itself. The overlay and the `water-ripple.js` refraction filter were both mounted inside the slot and clipped at its edges. This was confirmed in Chrome: the card had no overlay child and no `filter`.

**Decision:** the overlay is mounted on a `queueMicrotask`, which runs after the caller's synchronous append, so `closest()` finds the card. A `ResizeObserver` on the card keeps the drop origin and ring reach correct when the card reflows. The wave geometry (diameter `2.25 × maxDist`) was left unchanged: once the ripple was mounted on the card, its crest already reaches the bottom text.

## 2. "Confirming, please wait." spoke a different visual language

`/loading` and the editor/vacate submit overlay used a per-character magnify wave that scaled letters up to 1.42×. `/login/confirm` and the journals catalog used water. Two metaphors for "the app is waiting" read as inconsistent.

**Decision:** one language, water.
- Sunlit rings (`.card-water-ripple.loading-water-ripple`, the same rings as `/login/confirm`) are centred on the phrase.
- `water-ripple.js` refracts the phrase along each crest. `loading-transition.js` attaches the refraction when the overlay shows (or immediately on `/loading`, or when it is rendered visible for vacate's auto-resubmit) and detaches it on hide.
- Letters ripple **outward from the centre** with **no scaling**. `loading.go` sets `--d` (distance from the phrase's centre in characters) and each letter's lift-and-settle bob is delayed by `--d × 46ms`. The period is 1066 ms, the ring spawn interval (3.2 s ÷ 3 waves), so every ring launches a fresh text ripple.
- Reduced motion: static text, no rings.
- `loading.TransitionScriptPath` is the single source for the script URL. Pages embedding `loading.Overlay` now also load `water-ripple.js`.

## 3. Edge not loading tweets

Chrome and Brave render the embeds; Edge does not. The CSP is identical across browsers, so the most likely cause is Edge's **Tracking Prevention** classifying `platform.twitter.com` / `syndication.twitter.com` as social trackers. This is unverified: there is no Edge automation in this environment.

It exposed a real gap: a blocked embed can leave `createTweet()` never settling, so the ripple ran forever. **Decision:** a 12 s give-up timer falls back to the plain X link card. This is a failure net, not a wait: it never delays a working tweet and never replaces one already on screen. Verified with a stubbed never-settling `createTweet()`: the link card appeared at ~12.8 s and the other tweets were untouched.

Cache keys: `journal-media.js?v=13`, `loading-transition.js?v=2`, `loading.css?v=2`.
