Development moves to WSL. Still `CGO_ENABLED=0`. The site is generated in WSL and tested on the host. Not bare-metal Linux: there is no Ubuntu certification for the owner's Snapdragon X1E-80-100.

## What was measured (2026-11-27 to 28, on the owner's machine)

Microsoft Defender, consumer edition, real-time protection on (Surface Laptop 7th Edition, Windows 11 ARM64):

- **Thirteen detections since 9 October, all one name:** `Behavior:Win32/DefenseEvasion.A!ml`, severity Severe, each followed by a quarantine action. Every one was a file Go wrote: `go run` output under `%TEMP%\go-build…`, the compiled magefile, and Go's own `link.exe` once. None on `go.exe`, `gopls`, `staticcheck`, `mage.exe` or any .NET binary.
- **The verdict changes over time.** Every burst came after Defender received intelligence from Microsoft's cloud (event 2010). On 27 November it arrived at 19:51:15 and the first detection followed at 19:51:49. The same server binary had built successfully several times that evening; from then on it was refused. Defender logged no sample uploads (event 2050).
- **Cost on the native build:** a cold `go build` took 21 s when Defender was quiet and 85–90 s while Defender spent 116 core-seconds in one build. Three builds of the unmodified server in a row were refused.
- **For comparison:** about twelve freshly built, unsigned .NET executables were built and run on 28 November without a detection. No Defender rule exempts them; the launcher .NET builds is 99.8% the bytes of the SDK's own template.

The same build in WSL (Ubuntu 26.04.1 LTS, Go 1.27.4 linux/arm64):

- **No detection and nothing refused** in 9 builds over 115 s of work, in which Defender spent 4.4 core-seconds.
- **Speed:** cold build 13–15 s; 1.6 s after a one-file edit; `go test ./...` 20 s the first time, then 1.4 s; the linux/amd64 binary 13.7 s cold.
- **The hop:** a request from Windows to a server inside WSL costs 1.8 ms at the median and about 25 ms at p99, against 0.07 ms to a native server.

The owner's judgment, not a measurement: that defeating the antimalware is not standardized, and that Windows renews its provision despite user-level overrides.
