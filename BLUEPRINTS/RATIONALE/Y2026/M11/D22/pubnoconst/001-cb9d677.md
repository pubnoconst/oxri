## Rationale

1. **Eliminating Documentation Monoliths**:
   - In the previous iteration (`main`), `DECISIONS.md` and `HANDOFF.md` grew into large single-file monoliths, and the boundary between "what we decided" and "what we handed off" became blurry.
   - Starting fresh on an orphan branch inheriting only `.gitignore` gives us a clean slate while preserving the previous history on `main`, `rust-experiment`, and `fsharp-legacy`.

2. **Unified Date-Partitioned Rationale (`BLUEPRINTS/RATIONALE/`)**:
   - Every commit's rationale and context are now unified in small, immutable, date-sorted files under:
     `BLUEPRINTS/RATIONALE/Y<YYYY>/M<MM>/D<D>/<git committer name>/<Chronological Number>-<commit hash>.md`
   - This keeps individual documentation files focused, chronological, and easy for both humans and agents to navigate without reading a multi-hundred-line monolith.

3. **Actionable Session Pointer (`BLUEPRINTS/NEXT.md`)**:
   - `BLUEPRINTS/NEXT.md` tracks only:
     1. The latest commit hash.
     2. What is next on the author's mind.
     3. If a session ends amidst an active experiment, exact instructions on how to undo or reset that experiment.

4. **External Secrets (`../oxri-parent/`)**:
   - All secrets (`db.env`, `.ssh_host_key`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `TURSO_MAX_STORAGE_BYTES=4500000000`, `ADMIN_SSH_PUBKEY`) remain isolated in `../oxri-parent/` outside the Git working tree.

5. **PR-Driven Workflow with GitHub CLI (`gh`)**:
   - Major decisions and features will be developed via feature branches and merged through GitHub Pull Requests using `gh` (`gh pr create`, `gh pr merge`), producing a clean, reviewable history.
