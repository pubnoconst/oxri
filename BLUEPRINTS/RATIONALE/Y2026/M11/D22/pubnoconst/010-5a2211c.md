## 1. Context & Motivation

Principia Axiom #1 establishes zero external runtime dependencies (`CGO_ENABLED=0`), Axiom #3 states that *"All Inputs are evil"*, Axiom #5 dictates that *"The users are to never be treated as tech literate. At the same time malicious"*, and Axiom #8 enforces type-system correctness and capability tokens.

In the previous codebase (`main`), an in-depth security review uncovered two critical vulnerabilities in the SSH authentication flow:
1. **Login Hijack via "Approve Latest"**: The SSH server allowed usernames like `admin` or `root` to approve the *most recently created* pending login challenge. Any attacker visiting `/login` in rapid succession could steal an administrator's approval.
2. **Challenge Not Bound to Browser**: Any client presenting an approved 6-digit code to `/auth/status` could redeem an administrative session cookie.

Rationale 010 completely eliminates both vulnerabilities while delivering a clean, modern user experience for login and administrative profile management.

---

## 2. Changes Made

### A. Authentication Core & Hardening (`internal/auth/auth.go`)
- **Strict Token Verification**: Removed all shortcut usernames (`admin`, `root`, `oxri`). The SSH command or user parameter MUST match the exact 6-digit challenge token pending in memory.
- **Cryptographic Browser Binding**: When `/login` creates a challenge, the server generates a random 256-bit secret stored in an HttpOnly cookie (`res_imperii_login_binding`). The server only retains `sha256(bindingCookie)`. During `/auth/status` redemption, constant-time comparison (`subtle.ConstantTimeCompare`) ensures only the exact browser that initiated the login can redeem the session.
- **Single-Use Challenge Lifecycle**: Approved challenges are deleted immediately upon redemption, preventing replay attacks.
- **Capability Token Integration**: `auth.Service` integrates with `domain.SetupCapMinter()`. When an authenticated session is verified via `Authenticate(sessionID)`, it mints an unforgeable `domain.AdminCap` token.
- **SSH Listener Hardening**: Configures 10-second handshake deadlines to prevent slow-connection resource exhaustion, limits concurrent connections (semaphore of 10), and rejects `pty-req` and `env` channels.

### B. View Components (`views/login/`, `views/pilot/`)
- `views/login/login.go` & `login.css`:
  - 3-step authentication guide matching `main`.
  - Pure vanilla JS clipboard copy button (`onclick="navigator.clipboard.writeText(this.dataset.cmd)..."`), eliminating AlpineJS and removing the need for `'unsafe-eval'` in Content Security Policy.
  - Live pulse indicator and HTMX background poller (`hx-get="/auth/status..."`).
- `views/pilot/settings.go` & `settings.css`:
  - Administrative session status card.
  - Active Loopback SSH Key credential card with configured public key type (`ssh-ed25519`).
  - Passkeys (FIDO2 / WebAuthn Level 3) card marked "Pending HTTPS" for future rollout.
  - Form-based `POST /logout` button.

### C. Server Functions & Routing (`serverfns/auth.go`, `routes/routes.go`)
- `serverfns/auth.go`:
  - `RequireAuth`: Validates session cookie and mints `domain.AdminCap`.
  - `SanitizeRedirect`: Open-redirect defense restricting destination URLs to safe relative paths (`/`, `/pilot/user/settings`, `/book-i`, `/journals`).
  - `BuildSSHCommand`: Builds the exact command string `ssh -p <port> <token>@localhost`.
- `routes/routes.go`:
  - Mounted `/login`, `/auth/status`, `/logout`, and `/pilot/user/settings`.
  - Landing page dynamically shows "Settings" and "Log out" when authenticated, or "Log in" when unauthenticated.
  - Scoped CSS endpoints: `/views/login/login.css` and `/views/pilot/settings.css`.

### D. Comprehensive Unit Tests (`internal/auth/auth_test.go`, `routes/routes_test.go`)
- `TestAuthService_FullLifecycle`: Tests challenge generation, browser binding rejection, SSH approval, session creation, AdminCap minting, and revocation.
- `TestAuthService_RejectsGenericUsernames`: Asserts rejection of `admin` or unverified usernames.
- `TestAuthRoutes_FullFlow`: Tests end-to-end HTTP flow: unauthenticated redirect, challenge issue, SSH dial and sign, HTMX `HX-Redirect`, session persistence, and logout.
