# Rationale 008: Client-Safe Error Pages, Panic Recovery, and QR Reference Codes

- **Commit**: `28d28e1`
- **Author**: `pubnoconst`
- **Date**: 2026-11-22
- **Topic**: Implementation of client-safe error pages (400, 403, 404, 405, 408, 413, 500, 504), safe panic recovery middleware, UUID incident references, and pure Go QR codes.

---

## 1. Context & Motivation

Principia Axiom #5 states that *"The users are to never be treated as tech literate. At the same time malicious"*, and Axiom #6 states that *"The users should never be able to see what is under the hood"*.

Under no circumstances may database connection strings, SQL queries, directory paths, Go runtime panic messages, or goroutine stack traces be leaked to an HTTP response body. In addition, the visual appearance of error states should match the aesthetic dignity of `main` (clean card, `RES IMPERII` wordmark, status code typography, reference code, QR code for support, and return home link).

---

## 2. Changes Made

### A. Error Page Component (`views/errorpage/`)
- `views/errorpage/errorpage.go`:
  - `MessageForStatus(status int)`: Maps HTTP status codes to clean, human-understandable prose while concealing all internal technical jargon.
  - `NewReference()`: Generates a cryptographically random UUID v4 reference code.
  - `QRDataURI(ref string)`: Pure Go QR code generator (`github.com/skip2/go-qrcode`, zero CGO) rendering a 160px data URI (`data:image/png;base64,...`).
  - `Page(...)`: Gomponents layout rendering the error card matching the visual standard of `main`.
  - `Render(...)` / `RenderWithReference(...)`: Renders HTTP status headers, sets `Content-Type: text/html`, and outputs HTML.
- `views/errorpage/errorpage.css`: Scoped CSS with responsive typography (`clamp(4rem, 16vw, 6rem)`), clean card centering, white-backed QR container, and return link styling.

### B. Routing & Panic Recovery Middleware (`routes/routes.go`)
- `safeRecoverer`: Middleware that recovers from panics, generates a UUID reference code, logs the full stack trace and incident code internally to server logs (`log.Printf`), and sends only the sanitized error page with that reference code to the client.
- `r.NotFound`: Directs unmapped routes to `errorpage.Render(w, http.StatusNotFound, "")`.
- `r.MethodNotAllowed`: Directs invalid HTTP methods to `errorpage.Render(w, http.StatusMethodNotAllowed, "")`.
- `r.Get(errorpage.StylePath)`: Serves embedded component CSS at `/views/errorpage/errorpage.css`.

### C. Comprehensive Unit Testing (`routes/routes_test.go`)
- `TestErrorPages_NotFound`: Verifies 404 returns HTTP 404, `RES IMPERII` wordmark, reference code, and QR data URI.
- `TestErrorPages_MethodNotAllowed`: Verifies 405 returns HTTP 405.
- `TestErrorPages_PanicRecovery_NoLeak`: Simulates a runtime panic and asserts HTTP 500 response while strictly verifying that NO internal strings ("panic", "database", "goroutine", "stack", file paths) appear in the client response body.
- `TestErrorPages_CSS`: Verifies component CSS is served with `text/css`.
