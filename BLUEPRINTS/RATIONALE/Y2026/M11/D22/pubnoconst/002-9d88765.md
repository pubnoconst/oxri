## Rationale

1. **Why Go (`CGO_ENABLED=0`) Over Rust and F# / .NET**:
   - **Zero C-Toolchain & Zero Dynamic Linking**: Go (`CGO_ENABLED=0`) ships its own pure-Go compiler, linker, TLS stack, HTTP/2 stack, SSH stack, and SQLite/libSQL drivers, compiling into a single static binary in ~1 second without requiring a host runtime (like .NET) or dragging in `clang`, `gcc`, `msvc`, CMake, or `libc` dynamic linking (which frequently affects Rust crates for TLS and SQLite).
   - **Minimal Buildsteps**: Aligns directly with *Principia* #1 and #4—fast, self-contained compilation with minimal build steps and zero runtime dependencies.

2. **Enforcing Correctness via Go's Type System ("Parse, Don't Validate" + Capabilities)**:
   - Standard Go conventions rely too heavily on passing raw `string`, `int64`, `bool`, and exported-field structs across layers, leaving security and domain invariants at the mercy of human diligence.
   - To make illegal states unrepresentable at compile time in Go, we use **unexported struct fields across package boundaries**:
     - **Opaque Validated Domain Types (`internal/domain`)**: Types such as `MediaURL`, `Tag`, `TagSet`, `Prose`, `SafePath`, and `ValidatedEntry` have unexported fields and can *only* be minted by their boundary parser functions (`ParseMediaURL`, `ParseTagSet`, `ParseProse`, `ParseSafePath`). Database and handler functions accept only these opaque types, making it a compile-time error to pass unvalidated user input (`Principia` #3 & #5).
     - **Compile-Time Authentication Capabilities (`AdminCap`)**: State-mutating operations require an unforgeable `AdminCap` struct whose fields are unexported outside the authentication verification package. A handler cannot compile if it calls a mutating store method without first verifying admin authorization.
     - **Sealed Outcome Types**: Operations with distinct domain outcomes (such as saving an entry vs. requiring archive room) return sealed outcome types rather than ad-hoc sentinel errors that callers might forget to inspect.

3. **Foundational Charter (`BLUEPRINTS/Principia.md`)**:
   - Establishes the six core axioms of Res Imperii:
     1. Avoid runtime dependencies (`CGO_ENABLED=0`).
     2. Minimalism as the core essence of UX.
     3. All inputs are evil; men are, by nature, political creatures.
     4. Minimal buildsteps.
     5. Never treat users as tech literate, while always treating inputs as malicious.
     6. Never expose what is under the hood.
