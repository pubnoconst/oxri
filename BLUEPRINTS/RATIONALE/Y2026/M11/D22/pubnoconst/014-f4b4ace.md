# Rationale 014: Database Data-Integrity Hardening, Unified Domain Boundary, and Modular Decomposition

- **Commit**: `f4b4ace`
- **Author**: `pubnoconst`
- **Date**: 2026-11-22
- **Topic**: Addressing all database integration, quota atomicity, UTF-8 byte accounting, domain-persistence boundary, and file-decomposition findings from external code audit.

---

## 1. Context & Motivation

An external architectural audit identified six specific data-integrity and maintainability concerns in `internal/db`:
1. **Two Sources of Truth**: `internal/db` previously reimplemented validation rules via raw strings in `JournalInput` rather than using an opaque validated domain entity from `internal/domain`.
2. **Empty-DB Quota Bypass (3.A)**: `checkQuotaForCreate` and `checkQuotaForUpdate` returned early when `used <= 0` or `otherBytes <= 0`, allowing a single oversized entry to bypass the storage limit when the database was empty.
3. **Non-Atomic Quota Checks (3.B)**: Quota calculation and row insertion/update occurred outside a single transaction, permitting concurrent requests to race past the storage limit.
4. **UTF-8 Bytes vs SQLite Character `length()` Discrepancy (3.C)**: Go's `len(str)` measures UTF-8 bytes while SQLite's `length(col)` on `TEXT` columns measures Unicode code points, causing Go and SQLite byte estimates to diverge on multi-byte Latin diacritics (`Rōma`) and Greek (`Λόγος`).
5. **Non-Atomic Automatic Eviction (3.D)**: `AutoVacateBytes` previewed candidates and deleted rows in separate non-transactional queries.
6. **Growing Monolithic `internal/db/db.go` (687 lines)**: Needed decomposition into single-responsibility files in accordance with Principia Axiom #8.

---

## 2. Changes Made

### A. Unified Domain-Persistence Boundary (`internal/domain/journal.go`, `internal/db/validation.go`, `routes/journals.go`)
- Added opaque `domain.ValidatedJournalEntry` and `domain.ParseJournalEntry` in `internal/domain/journal.go` as the **single canonical source of truth** for journal character-set whitelisting, SSRF host checks, Title Case tag normalization, tag uniqueness, and length limits.
- `internal/db/validation.go` and `internal/db/sanitize.go` now delegate directly to `internal/domain`, eliminating duplicated validation logic.
- `routes/journals.go` parses incoming form submissions into `domain.ValidatedJournalEntry` at the HTTP boundary and calls `store.CreateValidated` / `store.UpdateValidated`.

### B. Quota Enforcement on Empty Databases & Single-Row Updates (`internal/db/quota.go`)
- Removed early returns when `used <= 0` or `otherBytes <= 0` in `checkQuotaForCreateTx` and `checkQuotaForUpdateTx`.
- Always evaluates $\text{projected usage} \le \text{maximum usage}$ regardless of whether the table currently contains 0, 1, or $N$ rows.

### C. Exact UTF-8 Byte Accounting in SQLite (`internal/db/quota.go`)
- Updated `usedStorageBytesSQL` to use `length(CAST(col AS BLOB))` instead of `length(col)`.
- In SQLite/libSQL, casting `TEXT` to `BLOB` measures the exact UTF-8 byte length rather than character count, matching Go's `len(str)` 1-for-1 for ASCII, accented Latin (`Rōma`), and Greek (`Λόγος`).

### D. Atomic Transactional Quota & Auto-Eviction (`internal/db/journal.go`, `internal/db/quota.go`)
- Added `s.writeMu` + explicit `s.db.BeginTx(ctx, nil)` around `CreateValidated`, `UpdateValidated`, `ToggleBookmark`, and `AutoVacateBytes`.
- Quota verification and `INSERT`/`UPDATE` now execute atomically inside the same transaction.
- `AutoVacateBytes` computes its candidate plan (`previewAutoVacateTx`) and deletes the selected candidate IDs (`deleteTx`) inside a single atomic transaction.

### E. Modular Decomposition of `internal/db/` (Principia #8)
- Replaced the 687-line `internal/db/db.go` with focused, single-responsibility modules:
  - `store.go` (~115 lines): Connection lifecycle (`Open`, `Close`), ID generation, `queryExecer` interface.
  - `schema.go` (~175 lines): DDL and transactional versioned schema migrations (`EnsureSchema`).
  - `validation.go` (~60 lines): `JournalInput` and delegation to `domain.ParseJournalEntry`.
  - `journal.go` (~260 lines): Transactional write operations (`CreateValidated`, `UpdateValidated`, `ToggleBookmark`, `Delete`).
  - `query.go` (~150 lines): Read queries (`List`, `ListFiltered`, `DistinctTags`, `Get`).
  - `quota.go` (~315 lines): Transactional content-budget enforcement and atomic `AutoVacateBytes`.
  - `sanitize.go` (~110 lines): Character-set delegation and input stripping helpers.

## 3. Verification & Adversarial Tests (`internal/db/db_test.go`)

Added dedicated tests verifying each audit finding:
- `TestQuotaEnforcedOnEmptyDatabaseAndSingleEntryUpdate`: Confirms oversized `Create` on an empty DB and oversized `Update` on a single-entry DB both fail with `ErrQuotaExceeded`.
- `TestMultiByteUTF8LatinAndGreekByteEstimationMatchesSQLite`: Confirms `store.UsedStorageBytes(ctx) == entry.EstimatedBytes()` for multi-byte Latin (`Rōma æterna`) and Greek (`Νόος`, `Λόγος καὶ ἀρετή`).
- `TestConcurrentCreatesNeverExceedQuota`: Spawns 10 concurrent goroutines writing against a 3-entry quota limit and verifies that exactly 3 succeed, 7 return `ErrQuotaExceeded`, and total usage never exceeds the cap.
