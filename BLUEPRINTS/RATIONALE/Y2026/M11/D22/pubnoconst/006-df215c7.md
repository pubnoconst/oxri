## 1. Context & Motivation

With Principia axioms codified in `BLUEPRINTS/Principia.md` (Axioms #1 through #8), Phase 1 establishes the executable foundation of `v2`:
1. **Zero dynamic C toolchain / runtime dependencies** (`CGO_ENABLED=0` enforced across all build targets).
2. **Minimal build steps**: Zero code generators (no `templ generate`, no Node/npm), single-step compilation via Go compiler and Mage.
3. **Discoverable structure**: Distinct directories for `views/`, `routes/`, `serverfns/`, and `assets/`.
4. **Per-component CSS alongside global design tokens**: Global typography, reset, and theme tokens live in `assets/css/site.css`, while component-specific styling lives next to the component (e.g. `views/landing/landing.css` served at `/views/landing/landing.css`).
5. **Exact reproduction of main landing page**: Hero typography ("A personal digital refuge"), navigation links, and theme toggle matching the visual identity of `main` without bulky framework baggage.

## 2. Changes Made

### A. Build System (`magefile.go`)
- Implemented pure Go build orchestration using `github.com/magefile/mage`:
  - `Build`: Enforces `CGO_ENABLED=0` and builds `./cmd/server` to `bin/server.exe`.
  - `Run`: Builds and executes binary.
  - `Test`: Runs `go test ./...` with `CGO_ENABLED=0`.
  - `Check`: Runs `go vet ./...` with `CGO_ENABLED=0`.
  - `Clean`: Removes `bin/` directory.

### B. Global Styling & Vendored Assets (`assets/`)
- `assets/css/site.css`: Complete modern CSS reset and design token system:
  - Font stacks: EB Garamond, Georgia, serif.
  - Light theme (warm neutral `#f5f4f0`, ink `#1a1a1a`, accent `#5c3d2e`).
  - Dark theme (Ayu `#0f1113`, surface `#15171a`, text `#e6e1cf`).
  - Reusable action buttons: `.btn-encouraged`, `.btn-neutral`, `.btn-destructive`.
- `assets/js/htmx.min.js`: HTMX v2.0.4 vendored directly (50,917 bytes). Zero CDN reliance.
- `assets/js/theme-toggle.js`: Vanilla JS double-click background handler toggling `dark-mode` class and persisting to `localStorage`.
- `assets/favicon.png`: Brand favicon.

### C. View Architecture (`views/`)
- `views/layout/layout.go`: Document shell constructed using `maragu.dev/gomponents`. Emits clean HTML5 document with title, CSS links, HTMX script tag, and theme script.
- `views/landing/landing.go`: Landing page component implementing the refuge hero, navigation buttons (`Explore Journal`, `Open Book I`, `Archive / Status`), and quote footer.
- `views/landing/landing.css`: Landing-specific card layout, button hover transitions, and responsive grid.

### D. Routing & Server (`cmd/server/main.go`, `routes/routes.go`)
- `routes/routes.go`: `github.com/go-chi/chi/v5` router mounting:
  - Static assets `/assets/*` from filesystem.
  - Per-component CSS routes (e.g. `/views/landing/landing.css`).
  - `GET /`: Renders `views/landing.Page()`.
- `routes/routes_test.go`: Unit tests validating `GET /` returns HTTP 200 and expected markup, `/views/landing/landing.css` is served, and `/assets/css/site.css` and `/assets/js/htmx.min.js` are reachable.
- `cmd/server/main.go`: Production-grade HTTP server configuration:
  - `ReadHeaderTimeout: 5s`, `ReadTimeout: 30s`, `WriteTimeout: 30s`, `IdleTimeout: 60s`.
  - Graceful shutdown on `SIGINT` / `SIGTERM`.

### E. Server Functions Skeleton (`serverfns/`)
- `serverfns/doc.go`: Clear architectural boundary for encapsulated RPC-style server operations (login challenges, journal mutations, quota vacate) invoked by routes and HTMX endpoints.
