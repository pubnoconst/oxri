## Rationale

1. **Context Windows Are Limited**:
   - Humans and AI agents both operate under finite context budgets. Monolithic files, sprawling packages with dozens of exported types, and shared mutable state overload attention and cause hallucinations, regressions, and missed checks.
   - Every module must be small, highly cohesive, and solve a single problem cleanly (e.g. `internal/domain` owns structural validation; `internal/auth` owns credential handshake and capability minting; `internal/db` owns persistence).

2. **The Type System Is Our Only True Defense**:
   - Sentinel values (e.g., empty strings meaning unauthenticated, 0 meaning default), boolean flags passed across handlers, and runtime checks that developers must remember to write (`if !auth.IsAuthenticated(...)`) fail under real-world pressure.
   - **Make erroneous states unrepresentable**:
     - Data must be parsed at the boundary into opaque types with unexported fields (`domain.MediaURL`, `domain.TagSet`, `domain.Prose`, `domain.SafePath`). No raw string can enter the domain logic or database layers.
     - Protected operations must require an unforgeable capability token (`auth.AdminCap`). Without this capability, the code literally will not compile.

3. **Thorough Documentation Traced to Commit Hashes**:
   - Code comments, package docstrings, and rationale files must explain *why* constraints exist, referencing relevant decision rationale files and commit hashes (e.g. `19b2630`). This makes the codebase immediately intelligible and maintainable for both future developers and future AI agent sessions.
