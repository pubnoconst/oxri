## Context

Right after scripture media shipped (066), the owner asked: "can you ensure the bible quote size does not break the character limit of a journal". In 066 the passage had its own 2,000-character cap alongside the entry's 2,000, so one entry could carry 4,000 characters.

## What changed

- **`domain.WithPassage`** refuses an entry whose own words plus the passage's text exceed `MaxJournalBodyLength` (2,000 characters, counted as Unicode characters). The message gives both counts. Every save path goes through it: create, edit, the Make Room re-send, and backup restore.
- **Editor**:
  - `scripture-picker.js` exposes `quotedLength()`, the loaded passage's length, or 0 before it loads.
  - `journal-editor.js` counts it. The counter reads `904 + 1096 quoted / 2000`, turns red with an explanation when over, and keeps Save disabled. It recounts whenever the scripture fields change.
  - The hint now reads "Up to 2,000 characters, a quoted Bible passage included."

## Why

The passage is part of the journal, so it counts toward the journal's limit. One limit, checked in one place (the domain), mirrored in the editor so the author sees it while writing.

## Verification

- Tests at exactly the limit and one character over, both in the domain and as a full save through the routes, using the fake provider.
- Browser check on the in-memory server with Psalm 119:1–16 (KJV, 1,096 characters): the counter split, the red state one over, clear at exactly 2,000, and the passage dropped from the count after switching back to Link.
- `go vet`, `staticcheck`, `deadcode -test`, all tests and the strict JS type-check pass.

## Not done

An entry saved between 066 and this change that is already over the shared limit is refused only when next edited. None is likely to exist.
