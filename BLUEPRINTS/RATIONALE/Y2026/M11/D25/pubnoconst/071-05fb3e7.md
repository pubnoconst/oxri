## Context

The owner found the Media and Scripture dropdowns' open lists "ugly blue, not idiomatic at all" and asked for overlays to be frosted glass. After the first pass they could not see any frost, and found that the Book list was not glass. They ruled that all overlays be frosted glass, written into the HIG with the blur standardised in kind, radius and intensity. They also asked for the test server to need no sign-in and to show the real Turso data.

## What changed

- **Select lists drawn by the page.** The open list of a `<select>` was the system's (blue highlight on Windows), which no CSS reaches. With `appearance: base-select` (Chrome 135+) the page draws it: float glass, an ink hover tint, ✓ on the chosen option at the end as in the Book list. Other browsers keep the system list.
- **Book list**: it was in place below the search box, pushing the fields down. It now floats over them as an overlay (`.book-search` relative, `.book-list` absolute), in float glass.
- **Confirming screen** (`views/loading`): veil glass instead of the solid page colour.
- **Two glasses, the only blur on the site** (HIG §4):

  | Glass | For | Tint | Blur | Saturation | Fallback |
  |---|---|---|---|---|---|
  | Float (`--depth-overlay-*`) | lists and menus over part of the page | depth-2 lifted 12% toward white, at 45% | 5 px | 1.8 | `--depth-overlay-solid` |
  | Veil (`--depth-veil-*`) | full-screen overlays | page colour at 62% | 14 px | 1.4 | `--depth-veil-solid` |

  A float also has a bright hairline edge and a 10% white top highlight. Glass sits inside `@supports (backdrop-filter: blur(1px))`, with the solid fallback outside it.
- **`TestBlurComesFromGlassTokens`**: every `backdrop-filter` must name one of the two blur tokens. No `filter: blur()` over content, and no other blur defined anywhere. A planted violation was caught.
- **`DEV_AUTO_LOGIN=1`** (`cmd/server/devlogin.go`): the local server signs every request in with one dev session. It is refused unless the server listens on 127.0.0.1, ::1 or localhost, is not on Render or `APP_ENV=prod`, and has an auth service. CSRF and freshness checks still apply. It prints a warning that saves change the connected database. Tested: the loopback, Render, prod and no-auth refusals, and that a request with a stale cookie is signed in.

## Why these numbers

- **Float.** The first float (68% tint, 18 px blur) reached the real editor but could not be seen: over a plain card it read as solid. It was tuned in the editor until the fields beneath showed as soft shapes.
- **Veil.** It covers text that should not be read while waiting, so it is denser and blurred past legibility.
- **One kind.** Both glasses are a Gaussian backdrop blur, a saturation lift and a translucent tint, so they read as the same material.

## Verification

- In Chrome, against the real database, in dark and light: the Media dropdown's list, the Book list (choosing Exodus still works), and the Confirming veil.
- `go vet`, `staticcheck`, `deadcode -test`, the strict JS type-check and all tests pass.
