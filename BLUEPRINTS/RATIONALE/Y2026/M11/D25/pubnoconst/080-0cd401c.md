## Context

Asked where else performance could go, Claude ranked the options. The owner chose three:
1. compression, so the lab matches production;
2. `Server-Timing`, to name the server's occasional slow first byte;
3. the render-blocking items.

The owner also plans to leave Render for a $2/month domain, served from a laptop if need be. They then asked for a light/dark switch at the top of every page, choosing the top-right corner, light/dark only, remembered across visits. Last: "change fade in to 100ms and ship it".

## What changed and what the evidence showed

- **Compression** (chi `middleware.Compress`, text types only): seeded-lab LCP fell 300–460 ms and bytes roughly halved. Production already compressed through Cloudflare, so this mostly makes the lab truthful; a laptop host without Cloudflare needs it.
- **`Server-Timing`** (`routes/servertiming.go`: `app`, plus `db` and `tweets` from the handlers): the lab reads it per run and in `-breakdown`. Warm, the server spends 0.3–2 ms per page.
- **Stale-while-revalidate caches.** `Server-Timing` named the spike at once: one run showed `server 1147.3` ms.
  - The cause: the entry snapshot and the book cache expired every 2 minutes (`readCacheTTL`), and the first reader afterwards waited on Turso.
  - Now a stale copy is served at once and one background refresh updates it. A local write still empties the cache and loads at once.
  - Tests simulate another server writing directly to the database.
  - Across 15 runs spanning an expiry, the worst server time was 2.2 ms.
- **`dot-matrix.js` is deferred**: 16–40 ms, near the noise.
  - Tried and reverted: scripts at `fetchpriority="low"`, which measured no better.
  - Not done: inlining `fonts.css`, which already arrives before `site.css`.
- **The page fade-in is 100 ms** (was 220 ms), for the body and the view-transition's new page. LCP does not move, since it counts the first visible frame. Pages reach full visibility 120 ms sooner.
- **The theme switch** (`layout.ThemeToggle`, `theme-toggle.js`, HIG §1.7):
  - **Placement:** top right of every page, a 44 px target, the moon in light mode and the sun in dark.
  - **Remembering:** the first visit follows the device; a tap is remembered in `localStorage`, replacing the old per-tab `sessionStorage`, which is carried over once.
  - **No flash:** the choice is applied before the first paint by the site's one inline script (`assets.ThemeInitJS`). The CSP allows exactly that script by its SHA-256 (`assets.ThemeInitCSPSource`). `TestThemeInitIsTheOnlyInlineScriptAndTheCSPAllowsIt` hashes the script as rendered.
  - **Phones:** at phone width the switch first overlapped the book's Edit button. Its row is now reserved (`--top-reserve`, 0 on desktop) and full-screen pages subtract it (`--full-height`). Six pages were checked at phone width: no overlaps, no new scrolling.
  - The double-click still switches.

`mage benchmark`, 10 runs, real data (before stale-while-revalidate and the fade change):

| LCP | Before | After |
|---|---|---|
| `/` | 1208 ms | 898 ms |
| `/book-i` | 1310 ms | 954 ms |
| `/journals` | 1642 ms | 1180 ms |
| `/login` | 1188 ms | 840 ms |

CLS stayed 0 on every page throughout.
