## Context

078 left one decision to the owner. As the web fonts replaced the fallbacks, Chrome laid the page out again: one 65–148 ms frame of style and layout at about 2.3 s on the budget-phone profile. On the seeded site a quote's body could also wrap one line differently (CLS 0.008). Nothing else could remove either. The owner: "Sure do it".

## What changed

- **The web faces** in the generated `fonts.css` are `font-display: optional`.
  - A face is used only if it is ready almost at once, which in practice means from the cache.
  - Otherwise the page keeps its size-matched fallbacks for the whole view while the web fonts download for the next page.
  - So a first visit is drawn in the fallbacks, and later pages in the site's own faces.
- **The local fallback faces** stay `font-display: swap`.
- **`TestFontFacesAreRegularAndHashed`** requires `optional` on every web face and `swap` on every fallback; no face may leave `font-display` unset (that defaulted to blocking text: 075).
- **HIG §2**: a page is drawn in one set of fonts, never swapped mid-view.

## Evidence

Seeded lab, 5 cold budget-phone runs:

## Trade-off

- **A reader's first page shows the fallbacks:** Georgia, Times New Roman or Noto Serif for the books; Arial or Roboto for the rest, each resized to match. Their later pages show EB Garamond, Figtree, Playpen Sans and Short Stack.
- **Lab runs measure first visits** (a fresh profile each run), so they always show the fallbacks.
