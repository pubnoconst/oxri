## Context

The owner pasted a Facebook CDN image link (about 520 characters, signed, with an expiry) into a new entry and found the preview ugly. The link field had `maxlength="128"`, so the browser cut the paste silently. The cut link still ended in `.png`, so the editor built an image; the CDN refused the broken signature, and the preview showed a broken-image icon inside the framed, shadowed image box.

## What changed

- **`views/editor/media.go`**: the link field takes up to 2,048 characters, so a paste arrives whole. The 128-character limit is unchanged: the editor reports it and the domain enforces it.
- **`journal-editor.js`**: a too-long link previews as "Link too long to preview." and the field error gives its length, the limit, and why image links copied from Facebook or Instagram fail (signed, expiring): link the post or host the image elsewhere.
- **`journal-media.js`**:
  - `fallBackOnError` swaps an image, video or audio that fails to load for the link card ("Image did not load", and so on). It applies in the editor and the catalog.
  - The link card (`createLinkFallback`) reads "Open on <site>", with the full address as its title, instead of printing the whole address.

## Why

A failure should look deliberate and say what to do. Cutting the paste turned a clear "too long" into a broken link with no explanation.

## Verification

- `go build`, `go vet`, `staticcheck`, the strict JS type-check and all tests pass.
- The owner tried it on the local server (in-memory database) before shipping.
