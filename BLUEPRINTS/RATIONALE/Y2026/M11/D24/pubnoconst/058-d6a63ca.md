## Context

The owner: "the tags window aren't too scalable. I can keep adding countless tags and in the catalogue tags creep up. Best solution would be to have a list of most used tags. And when a journal is being written, autosuggest tags."

Before this change:
- the catalog showed every distinct tag, alphabetically;
- the editor already suggested tags, from that same alphabetical list, capped at 8, so the tags the author actually uses never came first.

## Decision

- **`db.TagsByUse` / `TagsByUseCachedOnly`** replace `DistinctTags` / `DistinctTagsCachedOnly`.
  - They count each tag over the visible entries and order by count, then name.
  - They still come from the in-memory read cache, so there's no extra database work.
  - Readers count published entries only; the author counts all.
- **Catalog:** `CatalogView.TagGroups` splits the tags.
  - **Shown:** the `CatalogTagLimit` (12) most used, plus any selected tag, so a filter in effect is always visible and can be removed.
  - **More:** the rest, alphabetical (easier to scan a long list), behind a quiet "More tags (N) ▸" `<details>` that needs no script. Shut, it's text at the end of the row; open, its pills wrap on a row of their own. The marker rotation is disabled under reduced motion.
- **Editor** (`journal-editor.js`):
  - With the field empty, the label reads "Most used:" and offers the top tags.
  - While typing, tags that start with the text come first, then tags that contain it (case-insensitive, since tags are Title Case), each group still by use.
  - Tags already in the field are left out, and Tab still accepts the first suggestion.
- **HIG §5 (Tags)** records the ordering rule.
