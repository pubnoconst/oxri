## Problem

Owner's report after #39: journal cards showed **a black card as a placeholder** for the incoming tweet. The owner asked for nothing to be rendered while loading, and for the content to make room and be pushed down only once the tweet has arrived.

**Cause, introduced in #39:** while loading, the tweet slot held a 7.5 rem empty "ripple spacer" inside the tweet container. #39 replaced the container's `filter: drop-shadow()` with an identical-looking `box-shadow` (for performance). A drop-shadow only shadows *visible pixels*, so an empty box cast none. A box-shadow outlines *the box*, empty or not, so the reserved space became a dark rounded card.

## Decision

- **Nothing rendered or reserved while loading.**
  - The ripple spacer is removed entirely. The slot starts collapsed (`.is-pending`: zero height, overflow hidden), and the slot's own bottom gap is removed while pending (`.journal-media-slot:has(> .tweet-embed-container.is-pending)`).
  - Only the card's own content shows. The waiting cue is the card ripple, which already spans the whole card (RATIONALE 029). Its drop now lands where the tweet will open: horizontally centred on the collapsed slot, at its top edge.
  - An earlier attempt at a collapsed slot (RATIONALE 028 era) was rejected because "the ripple disappeared". At that time the ripple was trapped inside the slot. It now lives on the whole card, so collapsing the slot no longer hides it.
- **Push on arrival.** When Twitter reports the tweet's height, the FLIP push (RATIONALE 040) opens the slot from zero in one layout and slides the content below down to make room. The blocked-embed fallback and the "no measurable height" path also clear the pending state.
- **The shadow belongs to the revealed tweet only.** `.is-revealed` (renamed from `.is-expanding`, since no height animates any more) carries the `box-shadow` and the overflow clip. A pending slot has neither.

## Verification (Chrome)

- **Loading:** the slot is `is-pending`, height 0, no shadow, slot gap 0, and the card ripple is mounted with its origin at the slot's top edge (`--ripple-y: 64.5px`; the slot sits 65 px down the card). The card shows only date, tags and text, with no placeholder.
- **Arrival:** `is-pending` → `is-revealed` at 565 px with the shadow, **2** layout heights, FLIP animation running, nothing left over.
- **FLIP start, confirmed:** at the reveal frame the tags' layout position had jumped to 1009 while they were still drawn at 430 (their old spot), sliding from there.
- **Fallback:** a tweet frozen past 12 s became the X link card with the pending state cleared.
- **Measurement caveat (RATIONALE 039):** Chrome stopped drawing the automation window during some runs (8 frames in 7 s). Two odd results were traced: one to that, one to a test that overwrote Twitter's function without restoring it. Neither was a code fault. Smoothness on the owner's Pixel 10 is the real check.
