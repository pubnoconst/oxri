## Context

The owner: "refactor and remove dead/legacy code, functions and symbols."

Later, on verification: "Did you test for breakages? JS and CSS are not compile time checked and that bothers me." And: "install and use any static analysis tool to detect dead code, you have my full permission. Once done, ship it."

Go's compiler rejects unused imports and locals, but not unused functions, types, methods or package-level variables. Those compile silently.

## How dead code was found

1. **First pass, own scripts** (`deadcode` couldn't build offline at first):
   - every top-level Go symbol counted by identifier token, ignoring comments and strings, then by package-qualified name (`journals.Page`, `editor.Page`), because a bare name collides across packages;
   - JS functions and the members of shared `window.ResImperii*` globals;
   - CSS classes against Go and JS markup;
   - routes against their callers.
2. **Real analysers, once the owner allowed installing them:**
   - `deadcode` (`golang.org/x/tools`), from every `main`. It reports only `auth.GenerateTOTPCode`, a test seam other packages' tests use. With `-test`, nothing is unreachable.
   - `staticcheck` 2026.2.2: no unused code (U1000). It flagged three ST1018 and two SA1019 findings in tests, all fixed (`5357c6e`).
   - **TypeScript 5.6.3**, `tsc --allowJs --checkJs --noEmit --noUnusedLocals --noUnusedParameters` over the site's own scripts: no unused locals, functions or parameters and no unreachable code. It reported 85 type errors, all narrowing or undeclared globals rather than bugs or dead code; they're listed for plan step 6 in `NEXT.md`.
   - **PurgeCSS 6.0.0**, with all Go views and scripts as content: only the `:where(…):focus-visible` ring was rejected, a false positive (PurgeCSS doesn't evaluate `:where` with attribute selectors). No dead CSS.

   The JS and CSS tools were installed in a scratch folder; the project gained no dependencies.

## Guard: `TestScriptGlobalsMatchTheirCallers` (`02559b2`)

JS has no compiler to catch a broken cross-file call. This test reads the embedded scripts and fails if:
- a script uses `window.ResImperiiX.member`, or destructures it, and the defining script doesn't export it;
- a global exports a member no other script uses.

- **On the pre-cleanup code,** it reports exactly the dead exports removed here.
- **With `createMedia` dropped,** it names `journal-editor.js` as the broken caller.
