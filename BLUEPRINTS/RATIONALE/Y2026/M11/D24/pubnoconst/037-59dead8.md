## Press ripple ("your press was received")

The owner's brief: nothing told visitors their click "had been sent". Material uses a colour wave; this site's language is water. Pressing a link or button now drops a drop at the touch point, and the wave reflects off the window edges "like physics would".

- **Physics:** a wave reflecting off a straight wall is indistinguishable from a wave emitted at the same instant by a mirror-image source behind that wall. Each echo is therefore a mirrored source with half the energy (one bounce). All sources share one constant speed, so echoes arrive exactly on time. An echo exists only for walls the crest can reach within its run (0.8 × the window diagonal, about 0.8 s).
- **Refraction only:** the waves are invisible elements whose scale and opacity drive the shared `water-ripple.js` displacement over the page's linen. Nothing is painted (RATIONALE 030).
- **Navigation never waits.** If the next page is slow (a latency event), softer drops keep falling from the same point until it arrives, so a slow response reads as "working", never as a dead click. Form submits also count. Submits that raise the "Confirming" overlay hand off to it. A back/forward restore leaves the page still.
- **Boundaries:** it applies to links and buttons only, not clicks on empty background (a double-click there toggles the theme). Under reduced motion there is no ripple, only a static dim.
- **History:** the ripple was built and UI-approved earlier on the parked branch `v2-touch-ripple`. Its JS and CSS were unchanged on `main` since, so they were taken verbatim. The Go wiring was redone with typed asset handles (new `assets.TouchRippleJS`; the water engine now loads once in `layout.Doc`'s head, and the per-page includes are gone).

### Cost lessons from development

- **Unbounded rings froze the renderer.** Each wave's refraction map scaled with its ring (about 10,000 px for far echoes), and Chrome rasterised the whole image every frame. The fix: bounded reach, echoes only for reachable walls, per-frame culling of layers whose band misses the viewport, and no GPU layers for the invisible waves.
- **Measurements in a covered window are meaningless.** Chrome throttles a covered window to about 1 frame per second even when the page reports itself visible. Several "freezes" during development were that, not the code. The governor below ignores such samples.

## Adaptive quality governor (`ResImperiiWater.quality`)

Refraction cost scales with screen pixels and with each wave layer, so a fast laptop (the owner's Snapdragon X Elite) and a five-year-old phone cannot share one setting.

- **Levels:**
  - 3: drop plus every reachable wall echo.
  - 2: drop plus the nearest echo.
  - 1: drop only.
  - 0: off. No refraction anywhere (`attach()` returns a no-op), and a `.water-off` class gives the same static "received" dim as reduced motion.
- **Starting level:**
  - 3 by default.
  - 2 on touch-first (`pointer: coarse`), ≤ 4 GB or ≤ 4-core devices.
  - 1 with save-data, or on Safari, whose SVG displacement on HTML content has historically been slow. This was **not verified on Safari** (no device available), so it starts cautiously and has to earn more.
- **Learning from measured frames:** each run's 75th-percentile frame time is recorded. Above 24 ms steps down at once. Three *consecutive* runs under 18 ms step up, and an in-between run resets the streak. The level is remembered per browser (`localStorage`, `res-imperii.water-quality`; failures in private mode are tolerated).
- **Samples that are not evidence are discarded:** hidden tabs, throttled windows (p75 ≥ 250 ms), runs with too few frames, and runs interrupted by a new press. Interrupting a run also ends its frame sampler, which an early draft leaked.
- **Verified in Chrome:** echo counts per level (4 / 2 / 1, with Book I near the right edge), level 0 creating no overlay and no filter, step-down after a slow run, a throttled sample ignored, step-up only after three consecutive fast runs, and persistence.

## Settings polish (owner's UI review)

- **Add a passkey belongs to passkeys.** The label field, button and step-up / HTTPS notices were at the foot of the whole "Authentication Methods" section, below the TOTP card. They now live inside the Passkeys (FIDO2 / WebAuthn) card, under the enrolled list (`.methods-footer` renamed `.passkey-controls`, with tighter in-card spacing).
- **The session dot is alive.** The green "Administrative Session Active" dot emits a faint ring that spreads from 1× to 2.8× and fades over about 2 s, then rests about 1 s. It is the water language in miniature and subtle by design. Still under reduced motion. The animation was confirmed by sampling its computed transform and opacity.
- `/settings` requires a session, and signing in locally would have meant using the owner's real credentials. The view was therefore rendered from its Go function with sample data and inspected in Chrome.
