## Context

These are the quick wins from a maintainability review, all approved by the owner. The review found the Go backend in good shape (9 direct dependencies, typed core, 63.7% cross-package statement coverage), and named these debts:
- passkey sign-in at 0% coverage (next PR);
- an untyped, untested 1,805-line frontend (plan step 6);
- long view functions;
- dead, diverged code;
- an undocumented single-instance assumption;
- CRLF churn.

## Decisions

- **`internal/config` owns secret loading.**
  - There were two copies of the `.env` loader. `internal/auth/env.go` had **no callers** and had **diverged**: it lacked the UTF-8 BOM fix added in PR #16. A dead copy like that is exactly what someone "fixes" next while the live one stays broken. It is deleted.
  - The live loader moves out of `internal/db` (loading process configuration is not a database concern).
  - The secret-file locations were written out by hand twice (`cmd/server`, `cmd/backup`). Now `config.LoadSecrets(names...)` owns the search (`../oxri-parent/`, then `../`, each with `.env`) and each command names only what it needs. The backup tool still never reads `pw.env` (least privilege).
  - Tests cover the BOM, quotes, `export`, environment-wins, search order, and that unrequested files are not read.
- **LF everywhere (`.gitattributes`: `* text=auto eol=lf`).**
  - With `core.autocrlf=true` on the owner's machine and no attributes file, every checkout was CRLF. That caused phantom "modified" files in nearly every PR this session, made `gofmt -l` flag every file, and made embedded-asset content hashes differ between Windows builds and prod.
  - The attributes file overrides `autocrlf` for this repository. `git add --renormalize` changed **no** repository content (it already stored LF); only working copies change.
- **CI enforces formatting and vet.** Once the CRLF noise was gone, `gofmt -l` revealed four files that were genuinely unformatted (`internal/db/store.go` and three domain tests). They were invisible before because every file looked unformatted locally. CI now fails on `gofmt -l` output and runs `go vet` before the tests, so formatting can't drift again.
- **The single-instance constraint is written down** (Principia #1, README):
  - Sessions, sign-in counters (holds, lockout, global budget), rate limiters, WebAuthn ceremonies and the pending vacate submission all live in process memory.
  - That is correct for one Render instance. A second instance would silently split the state, halving brute-force protection and losing sessions between instances.
  - A restart, including a free-tier spin-down, signs everyone out.
  - Scaling out first requires moving this state to shared storage.
