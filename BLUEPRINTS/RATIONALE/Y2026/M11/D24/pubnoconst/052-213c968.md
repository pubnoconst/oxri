## Context

RATIONALE 051 proposed a second PWA step: cached public pages during Render cold starts, offline reading, and an offline page. The owner narrowed it to: "If offline, tell the user to go reconnect. I will not boil the ocean here."

## Decision

- **`/sw.js`** (`routes/sw.js`, served by `routes/serviceworker.go`) does one thing:
  - It handles only GET navigations. If the network fails, it returns the cached `/offline` page; otherwise it returns the real response.
  - It caches nothing else: no pages, assets, tweets, POSTs or HTMX requests. A form submitted offline still gets the browser's own error.
  - **Navigation preload is on,** so the page request starts while the worker boots. Having a worker shouldn't add a wait on every navigation on budget phones.
  - It is served from the root so its scope is the whole site, with `Cache-Control: no-cache` so a deploy reaches phones on their next visit.
  - **The cache name carries a hash of the offline page,** filled in by the server; the server panics at start if the placeholder in `sw.js` is missing. A reworded page means new worker bytes, so browsers reinstall the worker, re-cache the page and delete the old cache.
- **`views/offline`** renders a self-contained page:
  - inline style only, with no scripts, links or `/assets/` URLs, because nothing else is cached;
  - the site's `--page` / `--page-ink` colours for both system themes, with Georgia as the fallback when EB Garamond isn't cached;
  - copy: "You're offline". "Reconnect to the internet, then try again." "Try again" is `href=""`, which reloads the address that failed, because the worker serves the offline page under that address.
  - It follows the system theme only; a manual theme choice isn't applied there.
- **`assets/js/offline.js`** is loaded on every page. It:
  - registers the worker after `load`;
  - on `htmx:sendError` (for example the journal catalog's `/journals/content`), replaces the bottom-centre loader with "You're offline. Reconnect, then reload the page.", or "Couldn't reach the server…" when the browser still reports itself online.

## Verification

- **Route test:**

  - `/offline` returns 200 with the copy and contains no `<script>`, `<link>` or `/assets/`;
  - the landing page loads `offline.js`.
