## Problem

This is step 2 of the modularity / type-safety plan (see RATIONALE 032 and `NEXT.md`).

Cache-busting was manual: 38 hand-numbered `?v=N` references across views and tests, bumped with `sed` in almost every PR this session. A missed bump ships a stale asset to returning visitors. The URL strings were also untyped, so a typo or a deleted file would only show up as a broken page. Static files were read from disk at runtime (`ASSETS_DIR`, copied separately into the Docker image), while view stylesheets were already embedded strings: two mechanisms for one job.

## Decision

- **One `assets` package owns static files.** It embeds `assets/{css,js,favicon.png}` with `//go:embed` and exposes **typed handles** (`assets.SiteCSS`, `assets.JournalMediaJS`, …). The `Asset` struct's fields are unexported, so handles are declared only in that package. Each handle is checked against the embedded files when the program starts: a missing or mistyped file makes every process start fail (and every test), never a broken reference in production.
- **URLs carry a content hash.** `Asset.URL()` is `path?v=<first 12 hex chars of SHA-256 of the served bytes>`. View-owned stylesheets get the same through `assets.Component(StylePath, StyleCSS)`; each view package exposes a `Style` handle and `routes` mounts `style.Handler()`. Because the hash is computed from the bytes being served, the version and the content cannot disagree.
- **Caching follows the hash.** A request carrying the current hash gets `Cache-Control: public, max-age=31536000, immutable`; any other version, or none, gets `no-cache`. This is a performance win, since returning visitors no longer revalidate unchanged assets. Directory paths, traversal, non-canonical paths and unknown files still return the 404 error page (no listings).
- **Self-contained binary.** `Config.AssetsDir`, `ASSETS_DIR` and the Dockerfile `COPY` of `assets/` are gone; the deploy is one file.
- **Regression guards:**
  - `TestEveryFileHasAHandle`: a newly added file must get a typed handle.
  - `TestNoHandWrittenAssetURLs`: a `go/ast` scan fails if any non-test Go source contains a `/assets/…` or `?v=N` string literal. It immediately caught the route pattern, which now lives in the package as `assets.RoutePattern`.
