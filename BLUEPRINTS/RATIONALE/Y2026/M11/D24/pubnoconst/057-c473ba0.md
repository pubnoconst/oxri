## Context

From the owner's UI/UX review, X embeds were the strongest break in the site's look: their own sans font, colours and chrome, in the middle of Garamond on linen. They were also the heaviest thing on a budget phone, with X's script plus one iframe per tweet.

The owner asked for "an idiomatic tweet box".

Choices put to the owner:
- **Byline:** "Small round avatar", chosen over a text-only byline.
- **Video:** "Load X's player in place", chosen over linking out to X.

A throwaway comparison page then showed five card styles (Quotation, Clipping, Epigraph, Ledger, Plate) on the real linen, each with X, Reddit, Threads and Pinterest posts. The owner picked **Clipping**, with the note: "Be mindful that sometimes I will embed media links directly."

## Decision

### Data: `internal/tweet`

- **`ID`:** an unexported-field type made only by `ParseURL` or `FromString`, so it's always 1–20 digits and safe in a path or key.
- **`ParseURL`:** accepts `x.com`, `twitter.com` and their mobile hosts, with `/<handle|i>/status(es)/<id>`, and nothing else.
- **`Fetch`:** calls X's public syndication endpoint (`cdn.syndication.twimg.com/tweet-result`), the one X's own embeds use.
  - The `token` is computed exactly as X's script does: the id / 1e15 × π, in base 36, using V8's `DoubleToRadixCString` algorithm. It matched Node for 2,006 ids in the tweet range. X also accepted a longer, inexact token, so it isn't strictly checked, but we send the faithful one.
  - Responses are capped at 256 KB, with an 8 s timeout.
- **`Decode` treats X's response as untrusted.** It keeps only:
  - the author name, capped, with control and bidi characters removed (one real author's name contained them);
  - a handle matching `[A-Za-z0-9_]{1,15}`, or the post is refused;
  - the date;
  - the text: display range only, so the trailing media link is gone; t.co links shown as their display form; HTML entities undone (the page escapes again); at most 1,200 characters;
  - up to 4 media items, each https `pbs.twimg.com` only and with a positive size (videos and GIFs as their poster);
  - one level of quoted post, text only.
- **Rejected responses:** a post for a different id, or a tombstone (`ErrUnavailable`). `Load` re-checks stored rows, dropping foreign image hosts.

### Storage: `tweet_snapshots`, schema v7

- **Columns:** `id`, `status` (`ok` or `unavailable`), `body` (≤ 16 KB), `fetched_at`. The `CHECK` constraints mirror the Go checks.
- **It's a cache of public data, not the author's writing:**
  - not counted against the storage quota;
  - written by the background fetcher, so no `AdminCap`;
  - pruned when no entry links to the tweet.
- **Every snapshot is held in memory:** there's one per tweet in the archive, at about 300–550 bytes each for the owner's tweets. Page renders add no Turso round trip.

### Filling: `tweet.Filler`, started by `cmd/server`

- **It runs in the background, so a page never waits on X.** A tweet without a snapshot is drawn by X's embed this time and by the clipping from the next view on. Old entries fill themselves in, so no backfill command is needed.
- **It's polite and bounded:**
  - one request at a time with a 600 ms pause;
  - a 64-slot queue, where overflow is simply asked for again on a later view;
  - a 15-minute back-off after a failure;
  - posts X calls unavailable are asked about again after 7 days;
  - pruning runs at most every 30 minutes.
- **Tests:** a nil filler does nothing, so tests never touch the network.

### Drawing: `views/tweet` (Clipping)

- **The slip:** a `<figure>` slip of paper with `--page` background, a hairline border, a 3 px radius and a soft shadow, laid on the card's linen.
  - "X" and the date run along the top in small capitals, like a newspaper cutting.
  - The text is a `<blockquote cite>`, in paragraphs.
  - The quoted post sits in a small box.
  - 1–4 images carry `width`/`height`, so nothing jumps when they load: a single image keeps its own shape, and several share a 16:9 grid.
  - The bottom is signed under a dashed rule: a 24 px round avatar, name, @handle, and "View on X ↗" (`noopener noreferrer`).
- **No referrer:** images load lazily from `pbs.twimg.com` with `referrerpolicy="no-referrer"`.
- **Video or GIF:** the poster with a round play mark. Tapping it swaps the slip for X's player (`journal-media.js`), the only time X's script loads.
- **The catalog's compact cards** clamp long text to 7 lines and media to 13.5rem.
- **Direct media links are untouched**, per the owner's note. A linked image, video or audio file stays plain framed media.
  - The slot's image rule is now `.journal-preview-media > img`, a direct child, so it no longer styles images inside a clipping (it had been framing the avatar).
  - The CSS is folded into `journals.Style`.
- **The server marks a drawn slot mounted** (`data-media-mounted`), so `journal-media.js` leaves it alone.

### Remaining embeds, in `journal-media.js`

- **Built only near the screen:** an `IntersectionObserver` with a 600 px margin, so a page of un-snapshotted tweets doesn't load every iframe up front.
- **X's script is no longer preloaded** on the catalog shell.

**HIG §4** records the clipping rule: sites are named in text, never by logo, and direct media links are not clippings.

## Verification

- **`internal/tweet` tests:**
  - `ParseURL` accepts the right links and refuses look-alike hosts, schemes and over-long ids;
  - tokens match X's script for three real ids;
  - a synthetic response decodes to exactly what the box draws: entities undone, t.co links replaced, display range respected, blank lines collapsed, bidi characters dropped, foreign, http and zero-size media dropped, the video poster kept, the quoted post kept;
  - a snapshot survives a round trip, and a tampered row loses a foreign image;
  - a response for the wrong post, a tombstone, or an invalid handle is refused;
  - long text is clipped.
- **`internal/db` test:** put, get, cache, bad ids, status and oversize all checked; pruning updates both the table and the cache.
- **Route test:** a tweet with a snapshot is drawn by the server (mounted, play mark, sizes, no-referrer, escaped `<script>` in the author name and text). A tweet without one leaves an empty slot. The catalog references no X script.
- **Live, on an in-memory test server** with the owner's five public tweets: the filler fetched all five within seconds, and the catalog drew five clippings with 0 iframes and no X script.
  - Light and dark were checked.
  - The direct image entry stayed a plain framed `> img` with no clipping.
  - A play mark added by hand loaded X's player in place, and only then X's script.
- **Throwaway work:** live fetch and filler checks used temporary tests that weren't committed. The comparison page lived in the assistant's scratchpad.
- gofmt, vet and `CGO_ENABLED=0 go test -count=1 ./...` pass, including after merging `main` (PR #55): the card keeps both its clipping slot and its confirm slot.
