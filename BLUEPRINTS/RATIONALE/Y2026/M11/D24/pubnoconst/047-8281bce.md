## Owner's direction

After trying the phone loaders from RATIONALE 046 in production, the owner said:
- "Looks good, the animation isn't fancy but it will do." They had pictured each dot easing in and fading out, **like the sequential turn signal of a Porsche or a modern Mazda**. A Grok-style "solving Rubik's cube" matrix was mentioned as another idea.
- "More importantly, the loading tweet message is not centered in the journal entry card."
- "Drop the ripple and let GitHub archive it. We are going full dot matrix."

## Decision

- **Archive, then remove.** The `water-ripple` branch was pushed at `ac1ec45`, the last commit with the water as it shipped. It sits alongside `v1`, `fsharp-legacy` and `rust-experiment` as kept-on-purpose lineage.
  - Removed: `water-ripple.js` (the SVG displacement engine and its adaptive quality governor, RATIONALE 038–044) and `touch-ripple.js` (the tap ripple).
  - Removed: every ring, wave, cloth, refraction and `.water-off` rule and theme token; the catalog's page-wide ring; the Confirming rings; and the per-letter centre-out ripple (`SplitPhrase` / `CharToken`).
  - Removed: the phone/desktop split from RATIONALE 046. There is nothing left to split.
  - Net: −1,282 / +110 lines.
- **One loader, everywhere:** the 3×3 dot matrix plus a label, desktop included.
- **Turn-signal motion.** The column order (left → right) is the sweep, and each column has its own keyframes, so the fill is sequential but the fade is shared, as on a sequential indicator:
  1. each column eases on in turn (ease-out, like a lamp warming), about 0.12 s apart;
  2. all columns hold;
  3. the whole matrix fades out together (ease-in);
  4. a rest, then the next sweep.

  The cycle is 1.5 s. It is still opacity-only, so the compositor keeps it moving while the main thread is busy. Under reduced motion the dots stay still at 0.6.
- **Centred loading line.** RATIONALE 046 had aligned "Loading preview" to the left of the slot (`flex-start`). It is now centred where the tweet will open. With the water gone, the line is the slot's only pending state: the collapsed `is-pending` slot and its gap rule are removed. `flipPush` still removes the line and unrolls the slot into the tweet in one layout.
- **Navigation:** the page dims at once, and a slow navigation (180 ms) shows the bottom matrix on every device.
- **Kept:** the settings page's "live" status dot and its small pulse. It is a dot already, and its animation and comment no longer mention water.
- **Design principle updated** (in `NEXT.md` and the README): "Water shows as refraction, not paint" became "Waiting is one quiet 3×3 dot matrix: CSS-drawn, opacity-only, the same on every device."
- **Leftovers:** devices that ran the water may still hold `res-imperii.water-quality` / `res-imperii.water-off-at` in `localStorage`. Nothing reads them, and they are harmless.

## Follow-up in the same PR: `a83f6a4` (2026-11-24 15:02:18 +1000)

### Motions that mean something, seeded

The owner found the turn signal "too basic". A live page of six studies was reviewed: turn signal, comet, scanner, ripple rings, sliding puzzle, twinkle. The owner then assigned each motion a meaning, and asked that the puzzle and twinkle be **seeded**, so that cards loading together are not mirror images of each other:

| Motion | Meaning | Used for |
|---|---|---|
| Sliding puzzle (seeded) | the site is working on something you did | the Confirming overlay (entry saves and edits, Make Room), and POST navigations such as sign-in and book saves ("Working") |
| Twinkle (seeded) | downloading | tweet slots ("Loading preview", seeded per slot), "Loading entries…", following a link ("Loading") |
| Comet | waiting on you | passkey prompts ("Waiting for your Passkey…") |

- **`assets/js/dot-matrix.js`** (`ResImperiiDots`) draws all three with the Web Animations API, animating opacity and transform only. It uses a seeded RNG (FNV-1a hash → mulberry32); without a seed it picks a random one.
  - **Puzzle:** the gap starts on a seeded cell and takes a seeded 4–6 move walk that never steps straight back. Each move slides the neighbouring dot into the gap, and that dot brightens as it moves. Then the walk is retraced: scramble, then solve. Every dot ends where it began, so the loop is seamless. The period is 280 ms per move.
  - **Twinkle:** each dot glints at a seeded shuffle of nine evenly spread phases (with jitter), with a seeded period of 1.6–2.1 s.
  - **Comet:** not seeded. "Your turn" should look the same every time.
- **Typed motions in Go:** `loading.Puzzle`, `loading.Twinkle` and `loading.Comet` are values of a struct with an unexported field, so a view can't name a motion that doesn't exist.
- **Reduced motion:** nothing animates and the dots stay still. The fixed CSS turn-signal keyframes are gone.

### Fix: cards snapped open while their tweet pushed the content down

The owner reported that the card expansion was "a bit janky". Frame-by-frame recording found the cause: the card's bottom edge jumped from 338 to 530 px in one frame, with **no clip for the whole push**, while the content inside was still sliding.

- **Cause:** every tweet that arrives runs `flipPush`, which re-measures the neighbouring cards with `getBoundingClientRect`. That includes a running translate but not a running clip, so a half-unrolled card measured as already full height. The next tweet's push then cancelled the card's unroll and never restarted it.
  - This has been the case since the FLIP push was introduced (#39).
  - With twelve tweets arriving close together, nearly every card was affected.
- **Fix:** "first" is now the *visual* rect, the height minus the in-flight bottom clip, so an interrupted unroll continues from where it visibly is.

**Verification (Chrome, in-memory server, three tweets arriving 120 ms apart):**
- every card's edge now unrolls frame by frame; the largest single-frame step is 53 px, at the start of the ease-out, against a 192 px snap before;
- across 576 revealed-card frames, the tweet's visible bottom never crossed the content below: the minimum gap was the normal 13.6 px margin;
- a cold page load showed no slow frame during the push. One 50 ms gap came after it, and Chrome reported no long animation frame for it, so it happened outside the page's main thread (most likely Twitter's iframe).

**Test-harness lesson (again, see RATIONALE 041):** a recording run wrapped `createTweet` on top of a previous run's wrapper whose gates never opened, so no tweet loaded. Reload the page between runs instead of stacking wrappers.

**Puzzle verified across 200 seeds** (2,186 resting moments sampled):
- no two dots ever shared a cell;
- every dot started at home;
- the gap started on all nine cells across the seeds;
- periods of 2.24, 2.8 and 3.36 s occurred.

Tweet slots loading together each had a distinct glint signature. Search (GET) showed a twinkle labelled "Loading"; the batch form (POST) showed a puzzle labelled "Working"; the Confirming overlay showed a puzzle with its gap.
