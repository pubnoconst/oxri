## Context

The owner's report: "The edit dialogue and the preview dialogue in book-N editing do not have the same height."

- **Cause:** the text box had a minimum height of 36rem and a resize handle. The preview's minimum was also 36rem but it grew with its content up to 52rem, so any long book made the preview taller.
- After the first fix, the owner asked:
  - not to show "Markdown", "bytes" or "Preview": "simply display an error message once the char limit exceeds";
  - for Save changes and Cancel to sit in the centre.

The owner also reported that the top and bottom back links on a book page looked different. Measured in Chrome, signed out and with the signed-in Edit button added, they're identical: size, icon, font, opacity, colour and left edge. The owner then said they "must have seen it wrong". No change was made.

## Decision

- **One height for both panes.** `--book-pane-height` is `clamp(22rem, 72svh, 52rem)` side by side and `clamp(18rem, 60svh, 36rem)` stacked under 860 px. Both panes use it, and each scrolls inside itself. The text box has no resize handle, because resizing one pane would make them uneven again.
- **No labels or counter.**
  - The pane headings ("Markdown", "Preview") and the byte counter are gone, along with their CSS.
  - The text box takes its accessible name from the book's title; the rendered pane is labelled "How it will look" for screen readers only.
- **Length error only past the limit.**
  - `book-editor.js` reads the limit from `data-max-bytes`, set by Go from `db.MaxBookBodyBytes` rather than a second hard-coded constant in JavaScript.
  - Past the limit, a hidden `role="alert"` line appears between the panes and the buttons, worded like the journal editor's error: "Too long: 136.8 KB. The limit is 128 KB."
  - **KB, not characters:** the limit really is in bytes, and the HIG formats sizes as B / KB / MB.
  - The current size is rounded *up* to 0.1 KB, so text just past the limit reads "128.1 KB", not "128.0 KB".
  - **Save is disabled while over the limit.** The server would otherwise refuse the book and echo it back trimmed.
  - **`maxlength` removed:** it counted characters and silently cut a long paste.
- **Save changes and Cancel are centred.** The server-side error at the top is centred too, for consistency.

## Verification

- **Chrome:** the editor's markup was placed on the Book I page, which loads the same stylesheet; the editor itself needs a sign-in.
  - Both panes had the same top and height (607 px at a 929 px-wide window), with long and with short preview content.
  - **At exactly 131,072 bytes:** no error, and Save enabled.
  - **4 bytes over:** "Too long: 128.1 KB. The limit is 128 KB.", and Save disabled.
  - **140,000 bytes:** "Too long: 136.8 KB…".
  - The buttons' midpoint is 0 px off the action row's centre.
