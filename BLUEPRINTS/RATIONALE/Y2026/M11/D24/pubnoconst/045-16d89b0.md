## Problem (owner)

"Journal catalogue should be paginated, otherwise it's going to kill old Pixels or budget Samsungs."

`/journals/content` rendered every entry at once. Nearly every entry embeds a tweet, and each one is a cross-origin iframe plus Twitter's script work (`createTweet` runs for all of them; nothing is deferred). The DOM, the server-side Markdown rendering and the iframe count all grew linearly with the archive.

## Decision

- **12 entries per page** (`journals.CatalogPageSize`). This is small enough for budget phones, and 12 fills 1, 2 or 3 grid columns evenly. Only that page is rendered, so the cost is flat however large the archive gets.
- **Pages, not infinite scroll or "load more".** Both of those keep adding cards and iframes as you scroll, which is the very cost being removed. Pages also fit how the catalog already navigates: plain `/journals?…` links, with the shell passing its query to the HTMX content request.
- **`internal/paging`**, a small generic package (`Slice`, `Parse`, `Page`). `?page=` is untrusted input, so junk, zero and negatives mean page 1, and past-the-end means the last page (useful after deleting a page's entries). A `Page` is only made by `Slice`, so its `Number` is always a real page.
- **UI:** "← Newer · Page n of m · Older →" under the feed, only when there is more than one page. Entries are newest first, so the previous page is "Newer". The disabled end keeps its place so the status doesn't shift.
  - Page links keep the search and tag filters. Changing a filter (tag pill, search) starts again at page 1, because the filter URLs never carried `page`.
- **Bulk actions:** "Select all" becomes "Select all on this page" when paged. It only ever selected the cards on screen. "Unpublish all" and "Delete all" still act on the whole archive, as before.
- **Return to where you were.** Bookmark, publish and unpublish, delete and batch actions now redirect to the catalog page and filters they were taken from, read from the `Referer` header (the site sends `strict-origin-when-cross-origin`, so same-origin requests carry the full URL).
  - Only a same-host Referer with path exactly `/journals` is used, and only its path and query, re-encoded. Anything else goes to `/journals`, so this can't become an open redirect.
  - The existing return-to-permalink behaviour is unchanged.

## Verification

- **Unit (`internal/paging`):** short last page, exact multiple, empty list (one empty page, no neighbours), clamping both ends, and `Parse` of junk input.
- **Route test (30 entries, every other one tagged Dev):**
  - pages of 12 / 12 / 6, newest first;
  - `?page=999` → "Page 3 of 3" and `?page=abc` → "Page 1 of 3";
  - `tag=Dev&page=2` → "Page 2 of 2" with a Newer link keeping `tag=Dev`;
  - a one-page result has no pagination and plain "Select all";
  - bookmark and batch from `/journals?tag=Dev&page=2` return there;
  - an off-site Referer, `/login`, an entry permalink and no Referer all return `/journals`.
- **Chrome (throwaway in-memory server, 30 tweet entries):**
  - page 1 rendered 12 cards and 12 tweet slots, with "Page 1 of 3";
  - "Older →" opened `/journals?page=2`, starting at Entry 18;
  - bookmarking there came back to `/journals?page=2`.
