## Context

The owner set the current focus: real-world robustness, with a **Samsung Galaxy A02s** as the reference reader's phone and their own S9+ as the test phone. The water effect (RATIONALE 038–044) is SVG displacement over the page's cloth or a card: GPU work that budget phones can't spare, and it competes with tweet loading at exactly the moment a loader is showing. On the owner's Pixel 10 it had already throttled itself off (RATIONALE 044).

The owner proposed a different UX for phones: a simple animation such as "Confirming, wait..." and "Loading preview..." with dots, or the 3×3 dot matrix that TUI apps use.

## Owner's choices

- **All touch phones** get the new loaders, the Pixel 10 included, rather than only devices the quality governor judged weak. That gives one predictable phone experience, while desktop keeps the water.
- **A 3×3 dot matrix plus a label.**
- **The tweet slot shows one quiet "Loading preview" line on phones.** This deliberately relaxes the "nothing rendered while a tweet loads" rule from RATIONALE 041. That rule was about a *box* (the shadowed placeholder card); this is a single low-contrast text line with no box or shadow.

## How

- **What counts as a phone:** `(pointer: coarse)`, meaning touch is the primary input. Touchscreen laptops report a fine pointer, so they keep the water. CSS media queries and `ResImperiiWater.isPhoneUI()` use the same query, so script and styles can't disagree.
- **No water on phones:**
  - `attach()` is a no-op;
  - `touch-ripple.js` makes no tap ripple;
  - CSS hides every `.card-water-ripple` (card loaders, the catalog's page-wide ring, the Confirming rings).
- **One loader component:** nine dots lit in a diagonal sweep (each dot's delay is its row + column), next to a label.
  - **CSS dots, not glyphs.** Braille spinner characters depend on the phone's fonts.
  - **Opacity-only animation.** The compositor keeps opacity animations running while the main thread is busy (tweet scripts, HTMX swaps). A JS spinner that swaps characters on a timer would freeze exactly when it's needed.
  - **Hidden by default and shown only on phones,** so the Go helper can stand in for plain loading text everywhere.
  - Built by `loading.Dots` in Go and `dotLoading()` in `journal-media.js`, both producing the same markup.
- **Where it appears on phones:**
  - **Tweet slot:** `showLineLoader` puts "Loading preview" in the slot (`is-loading-line`, a separate class from the collapsed `is-pending`, so the collapse and gap rules don't apply). `clearPending` removes the line *inside* the FLIP layout step, so the slot unrolls from the line into the tweet with the existing push. The link-card fallback and the no-height path clear it too.
  - **Catalog:** the "Loading entries…" placeholder gains the matrix.
  - **Confirming overlay and page:** the matrix sits beside the phrase, and the per-letter ripple stops on phones, so the dots are the only motion.
  - **Navigation:** the page dims to 0.6 as before. If the navigation is still pending after 180 ms, a small fixed "Loading" matrix appears at the bottom, not dimmed. Form submits get the same treatment.
- **Desktop:** unchanged.

## Verification (Chrome, throwaway in-memory server; phone state simulated)

Desktop Chrome can't report a touch pointer. Scripts were given `(pointer: coarse)` = true, and the stylesheets' coarse rules were applied as written. Tweets were held for 5 s by wrapping Twitter's real `createTweet`, which still ran afterwards.

- **Catalog:** both tweet slots showed a 26 px "Loading preview" line with the dots. No ring was displayed and no card had a filter. On arrival, one slot became the tweet (line gone, `is-revealed`); the other fell back to the X link card (line gone).
- **Confirming:** dots beside the phrase, rings hidden, no refraction, letters still. A first reading showed the letters still animating. That was an artefact of the simulation: the injected rules came before `loading.css` in document order. Re-checked with them last, which is their real order inside `loading.css`.
- **Slow navigation:** `main` dims to 0.6, and the "Loading" matrix shows at full opacity at the bottom.
- **Real smoothness can only be judged on the phone** (S9+ at HD+ resolution).
