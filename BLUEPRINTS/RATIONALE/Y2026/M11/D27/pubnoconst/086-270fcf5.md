## Context

1. **Preview cards were cluttered.** Each catalog card stacked a top header bar (entry date alongside `Unpublished` and `★` pills), a post clipping with `"X"` and a second date at the top, text, tall media, a dashed rule with avatar and handle at the bottom, centred tag pills, and centred excerpt prose—seven competing horizontal bands in one narrow card.
2. **Full journal entries stacked source above commentary unconditionally.** Opening `/journals/{id}` placed even a short quotation or compact image across the top and pushed all commentary underneath, wasting horizontal reading room instead of setting source and commentary side by side like a printed broadsheet.

Both designs were prototyped in a standalone throwaway browser against the live archive on branch `card-preview-ideas` before touching production views, tagged at each approved milestone (`preview-cards-v1`, then `newspaper-entry-v1`), and codified here in `HIG.md` and `NEXT.md`.

## What it decided

### 1. Universal preview cards (`preview-cards-v1`, `d5e8e63`)

Every element keeps an invariant relative position, and a card grows strictly as it carries more content:

| Post kind | Rule | Layout |
|---|---|---|
| **Caption (`1C`)** | `media` present and `≤ 80` characters (including `0`-char media posts) | Full-bleed media fills the clipping. Both the top-left frosted author pill and the bottom caption scrim start hidden (`opacity: 0`) at rest; they ease in (`240 ms cubic-bezier(0.22, 1, 0.36, 1)`, `opacity` + `4 px` `transform`) on cursor hover, keyboard/tap focus (`:focus` / `:focus-within`), or central-band scroll focus on touch displays (`(hover: none), (pointer: coarse)`), and ease out on leave. |
| **Newspaper snippet** | `media` present and `> 80` characters | Same top-left author row (`avatar` + stacked `Name` / `@handle` + quiet `↗`) and right-hand text as a pure statement, adding only a compact square thumbnail (`~4.85rem`, with video play mark or `1/N` photo count) on the left. |
| **Pure statement** | no `media` | Circular avatar + `Name` / `@handle` at the top-left, with full-width statement prose directly below. |

The outer catalog card collapses into three left-aligned layers that appear only when present: (1) quoted clipping, passage, server still, or link slip, (2) entry excerpt (`--font-entry`), and (3) one quiet baseline footer (`Date · Tags` on the left, subtle `Draft` and `★` on the right), followed when signed in by the frozen author action bar (`HIG §4`).

### 2. Newspaper full-entry reading layout (`newspaper-entry-v1`, `19aeb9c`)

When an entry is opened at `/journals/{id}`:

| Case | Condition | Layout |
|---|---|---|
| **Newspaper float (`wrap-left`, default)** | Any source except the exceptions below | Inside a `display: flow-root` stage, the unclamped source floats **top-left** (`clamp(15.5rem, 43%, 22.5rem)`). Commentary begins at **top-right** on the same horizon and expands to **100% horizontal width** once it clears the bottom of the source (`< 680 px` viewports release the float to one column). |
| **Media + rich description (`stack-rich-source`)** | Source has `media` and `> 80` characters (or `media` + quoted post) | The source itself pairs a left plate with unclamped right-hand text across the top; the author's commentary starts cleanly **at the bottom** across the full width. |
| **Concise source + early code (`wrap-compact-code`)** | `<pre><code>` appears before `< 420` chars of prose **and** source is concise (`≤ 140` chars, no media) | The top-left source slip **compresses** (`clamp(12.5rem, 29%, 15.25rem)`, tighter padding and type) while `<pre>` uses `contain: inline-size` + `overflow-x: auto` without clearing, so the quote and the code body **coexist side by side in one horizontal space** (`~71%` on the right), and prose below still wraps out to `100%`. |
| **Long/media source + early code (`stack-early-code`)** | `<pre><code>` appears before `< 420` chars of prose **and** source is `> 140` chars or carries media | Source stays across the top and commentary + `<pre><code>` start cleanly **at the bottom** so neither the quote nor the code block is squeezed. |
